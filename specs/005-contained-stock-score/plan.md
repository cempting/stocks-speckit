# Implementation Plan: Contained Stock Score Summary

**Branch**: `005-contained-stock-score` | **Date**: 2026-10-30 | **Spec**:
[spec.md](./spec.md)

**Input**: Feature specification from
`/specs/005-contained-stock-score/spec.md`

## Summary

Simplify the contained-stocks comparison tape to retain its charts, ticker, name, and price while
replacing the four component-score columns with one Score column. Score is the equally weighted
average of Quality, Growth, and Cash Flow only when all three component values are available.
Otherwise, the table shows an explicit non-numeric state and does not trigger a score load.
Remove the redundant Observed and Chart Status columns without removing row-level chart
disclosures for missing, insufficient, or placeholder evidence.

## Technical Context

**Language/Version**: Python `>=3.12,<3.13`.

**Primary Dependencies**: Existing Streamlit, pandas, and Altair dependencies; no new
dependencies.

**Storage**: N/A. The feature derives a display value from the existing in-memory peer-score
result and does not persist an aggregate.

**Testing**: pytest, Streamlit AppTest, Ruff, and strict Pyright.

**Target Platform**: Browser-hosted Streamlit application.

**Project Type**: Single Python Streamlit application.

**Performance Goals**: Building the contained-stocks table remains local, linear in the displayed
row count, and introduces no remote requests.

**Constraints**: Reuse the existing explicit score-load action and peer-score evidence. A numeric
Score requires finite 0–100 Quality, Growth, and Cash Flow component values, each in the
`available` state. Missing, insufficient, unavailable, error, and not-loaded states must remain
visible and must never become zero or a partial average.

**Scale/Scope**: One projection change for the contained-stocks tape only. Sector and industry
tapes, score acquisition, peer-score formulas, persistence, and stock-detail scorecard
presentation are out of scope.

stock-detail rendering.

## Phase 0 - Research Resolution

See [research.md](./research.md). The existing scorecard is the sole source of the three
components. Equal weighting is a local arithmetic mean conditioned on all three available,
finite component values. Existing table chart cells already own evidence disclosures, so the two
metadata columns can be removed without hiding those states.

## Phase 1 - Design and Contracts

1. `StockTapeRow` remains the handoff from the Discovery workflow to the table projection; no
   persistent entity changes.
2. The projection derives one `OverallScore` result from `PeerScorecard` and the row's existing
   `score_state`/`score_reason`.
3. The projection emits table columns in this order: Price chart, Volume chart, Ticker, Name,
   Price, Score, Instrument ID, Resolution. Internal identity columns remain hidden by the
   renderer.
4. The table keeps price/volume chart cells and their direct unavailable/insufficient captions.
   It removes only the Observed and Chart Status columns.
5. Tests verify the calculation, all non-numeric state mappings, absent legacy columns, no
   implicit score load, and retained chart evidence disclosures.
