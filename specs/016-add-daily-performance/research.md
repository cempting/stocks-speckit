# Research: Daily Performance

**Date**: 2026-11-08 | **Status**: Design decisions resolved; layout implemented, with final
touch and cross-surface acceptance pending.

## Decisions and Alternatives

| Decision | Rationale | Rejected alternative |
|---|---|---|
| Pure exact-endpoint daily helper in the existing domain module | Deterministic fractional arithmetic, isolated from clocks/calendars. | New service or generic configurable period engine. |
| Application resolves requested-date official sessions | Weekends/holidays and missing prices are distinct; entity/benchmark use the same pair. | Last two non-null rows, calendar-day subtraction or stale observed-date fallback. |
| Unified six-period representation results with value/reason entries | Daily and supported longer horizons remain available independently; no bare nullable result loses failure context. | Separate representation daily API, all-or-nothing display, fabricated zeros or silent omissions. |
| Exact approved ETF/basket evidence | Both entity tapes use reviewed representations; every basket member keeps approved weights and matching endpoints. | ETF-only handling, parent proxies, inferred members or renormalization. |
| Benchmark required only for relative daily | Absolute daily remains usable without benchmark; relative is entity minus matching benchmark. | Shared failure block blanking all periods or silent Absolute fallback. |
| Shared display mapping and renderer | Existing formatting/palettes/metadata are reused; `1 day`/`1 year` are captions for `1d`/`12m`. | Bespoke daily cells, new thumbnail or ranking controls, calculation-key renaming. |
| Scoped native header, row scrolling and details | Preserve existing state/callbacks; provide readable phone controls and non-hover evidence. | Page-global CSS, wrapped 390px strip, shrinking/clipping values or page-wide scrolling. |
| Heading left, controls stacked right through 640px | The user selected this arrangement and the existing narrow cutoff; wider tablets keep desktop behavior. | Heading above both controls, full-width basis below the heading, or extending the cutoff to 768/1024px. |
| One scoped native container around existing entity controls | Reuse the current header's CSS-grid pattern without duplicate widgets, new state or a layout dependency. | Device detection, viewport JavaScript, custom components, global column rules or separate mobile widget copies. |
| Keep the existing return palettes and enforce contrast in tests | A deterministic sweep of the current light/dark neutral-to-gain/loss ramps exceeds the WCAG AA normal-text threshold; retain the visual design and guard every generated return-text pair against regressions. | Unnecessary palette replacement or checking only the three endpoint colors. |
| Treat 390px chart and scroll behavior as explicit browser acceptance | The requirement is visual and input-dependent: charts remain 84px high with plotted content visible, and the overflowing strip exposes a persistent local cue and is fully reachable by touch/keyboard. | Treating CSS/AppTest assertions or a transient browser scrollbar as proof of usable phone scrolling. |

## Return Palette Contrast

**Decision**: Keep the current gain/loss/neutral colors. In both themes, test every foreground/background
pair generated by the return styles against WCAG AA: at least 4.5:1 for normal text and 3:1 for large
text. Return status remains understandable from the signed numeric value and zero even without color.

**Evidence**: The current text foregrounds are `#17212b` (light) and `#edf3f7` (dark). A deterministic
1,001-step sweep of the neutral-to-gain and neutral-to-loss color ramps gave minimum contrast ratios
of 4.8373:1 in light mode and 6.3712:1 in dark mode; neutral backgrounds measured 15.0113:1 and
14.2462:1 respectively. This exceeds the normal-text threshold throughout the sampled ramps.

**Validation decision**: Add an automated regression in the performance-table tests that exercises both
themes and all generated gain/loss/neutral text/background pairs, including intermediate ramp colors.
Use actual rendered styles or the existing style helper rather than hard-coding only palette endpoints.

## Heading/Control Layout Research

**Decision**: Reuse the existing three native columns inside an entity-only keyed container.
At widths through 640 CSS pixels, scoped grid placement gives a left heading spanning two rows,
Thumbnail period upper right and Performance basis lower right. Above 640px, retain the
existing 2:2:2 column layout and order. The main Discovery header and Contained stocks are
separate surfaces and keep their existing behavior.

**Rationale**: `discovery_page.py` already uses a keyed `discovery_header` container,
`st.columns`, and `_DISCOVERY_HEADER_STYLE` with an inclusive 640px media query. Its existing
AppTests in `tests/app/test_market_selection.py` check native structure, order, scoped styling
and selection preservation. This is concrete prior art for the smallest current change.
Current entity controls use one heading/period/basis row with stable keys and defaults;
retaining those widgets avoids widget-cleanup/state migration risks.

**Alternatives considered**: Separate phone controls could duplicate keys or lose selections;
global CSS could change stock views and other tabs; a new mobile component or sizing script
adds dependencies and rerun/state behavior not required by FR-012. The user explicitly rejected
the wider 768/1024px cutoffs in favor of 640px.

**Validation decision**: Add failing native-structure/state/request regressions, then measure
both entity groups at 390/640px and desktop preservation at 641/1440px in both themes.
Native container structure and CSS-selector assertions are not proof of browser geometry.
Verify every option with touch/keyboard and record actual CSS width, positions and overflow.
No new layout tests or browser passes were executed during planning.

Streamlit's [columns](https://docs.streamlit.io/develop/api-reference/layout/st.columns)
and [container](https://docs.streamlit.io/develop/api-reference/layout/st.container)
documentation describe the native primitives. Repository behavior, not assumptions about a
newer documentation version's DOM, is the implementation and validation baseline.

## Boundaries

- Domain: [sector_performance](../../packages/market-data/src/market_data/domain/sector_performance.py)
  and [industry_representations](../../packages/market-data/src/market_data/domain/industry_representations.py).
  `PerformancePeriod` supports `1d`; `calculate_absolute_performance` accepts one selected period
  while retaining its default five-period contract and legacy `PerformanceResult`.
- Calendar: [market_sessions](../../src/market_leadership/application/market_sessions.py) and
  [exchange_calendar](../../src/market_leadership/application/exchange_calendar.py) supply explicit adjacent dates.
- UI: [discovery_page](../../src/market_leadership/ui/workflows/discovery_page.py),
  [performance_table](../../src/market_leadership/ui/performance_table.py) and
  [progressive_tape](../../src/market_leadership/ui/components/progressive_tape.py) reuse loaded histories,
  nullable percentage projections, shared palettes and native widgets.

Daily lookup precedes existing observed-date chart/long-period cropping. Missing requested-date
endpoints remain unavailable rather than triggering acquisition or interval shifts.
Preserve valid longer arithmetic, stock behavior and five-period ranking/snapshot outputs;
independent display availability and the typed Python return-shape migration are intentional.

## Validation

Extend existing domain, completed-session, workflow and renderer tests before source fixes.
Check exact units/endpoints, literal captions/order, independent availability, approved baskets,
both bases/themes, state/requests and stock preservation. Browser checks measure actual widths
and use real touch/keyboard input for scrolling/details; header presence, hover or DOM clicks
alone are insufficient. Include the 640/641px heading/control boundary without extending
the existing row or main-header acceptance widths. The palette regression checks WCAG AA for
all generated return text/background pairs in both themes. At 390px, browser acceptance additionally
measures 84px charts and verifies plotted content is not clipped, the persistent local-scroll cue is
visible, touch and keyboard reach the last strip field, and page-level horizontal overflow is zero.
[Quickstart](quickstart.md) retains observed history and pending gates.
