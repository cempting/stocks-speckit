## Summary

Constrain the contained-stocks table to Price chart + 50 MA, Volume chart, Ticker, CAP Type,
and Total Score. Retain Name privately for the Ticker button and stock details.
Rename the established Score display to Total Score without changing its
equal-weight, three-component rule. Preserve the current market capitalization value already
obtained by the existing explicit fundamental-score action, then classify it as Large (>= $10B),
Mid (>= $2B and < $10B), or Small (< $2B). No additional market-data action is introduced;
before or without valid capital evidence, CAP Type is Unavailable.

## Technical Context

**Language/Version**: Python `>=3.12,<3.13`.

**Primary Dependencies**: Existing Streamlit, pandas, Altair, and yfinance dependencies; no new
dependencies.

**Storage**: N/A. Current market capitalization is retained only in existing cached
fundamental-score evidence and is not persisted as a separate table record.

**Testing**: pytest, Streamlit AppTest, Ruff, and strict Pyright.

**Target Platform**: Browser-hosted Streamlit application.

**Project Type**: Single Python Streamlit application.

**Performance Goals**: Table projection remains local and linear in row count. The table makes
no network request; CAP Type becomes available only as a result of the existing explicit
score-load action.

**Constraints**: Use only current, finite, positive capitalization values carried from the
selected provider's existing fundamental profile. Keep the existing explicit load action and its
cache behavior. Before a successful load, after a failed/insufficient load, for placeholders, or
when capitalization is missing/invalid, display CAP Type as Unavailable. Do not change
peer-score formulas, score-detail presentation, chart geometry, or moving-average calculation.

**Scale/Scope**: One contained-stock table projection and the narrow evidence handoff that
supplies its current capitalization value. Sector and industry tables, stock detail, historical
capitalization, new provider calls, and data persistence are out of scope.

**Structure Decision**: Extend existing fundamental evidence and `StockScoreEvidence` with the
provider's current capitalization value and as-of date. Keep threshold classification and visible
column construction in the contained-stock projection. The workflow wires the established
evidence into rows and does not issue data requests.

## Phase 0 - Research Resolution

See [research.md](./research.md). The selected provider's existing fundamental profile contains
the current `marketCap` value, but `FundamentalBundle` currently drops it. Retain the valid,
positive value with its fetch date in the existing explicit score-evidence path. Do not use the
peer-score point-in-time market-cap requirement for CAP Type: that stricter rule protects
historical cash-flow percentile calculations and does not apply to a current display
classification.

## Phase 1 - Design and Contracts

1. Extend in-memory fundamental and score evidence with `market_cap?` and `market_cap_as_of?`;
   validate a numeric finite positive profile value and retain no value on profile errors.
2. `StockTapeRow` receives that optional value from `StockScoreEvidence`. A pure projection
   classifies it: Large >= $10B; Mid >= $2B and < $10B; Small < $2B; otherwise Unavailable.
3. Render the contained-stock comparison columns in this exact order: Price chart, Volume chart,
   Ticker, CAP Type, Total Score. Keep Name in the private projection for the combined ticker/name
   button, alongside internal selection fields.
4. Rename Score to Total Score while preserving the existing numeric and non-numeric state
   contract. Price and volume chart-cell disclosures remain unchanged.
5. Test provider extraction and evidence handoff, all CAP thresholds/invalid values, final column
   order, explicit no-load/unavailable behavior, and retained chart/placeholder disclosures.
